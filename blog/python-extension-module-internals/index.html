核心思想：Python 扩展模块本质上是一个使用 Python C API 开发的动态库，用于将原生代码（C/C++ 等）集成到 Python 运行环境中。

.pyd（Windows）和 .so（Linux）只是不同平台上的动态库格式。

一个符合 Python 扩展规范的动态库。

为什么普通 Cython 会慢

不是因为多了一层动态库。

真正原因：Python C API 为支持动态语言特性，需要完成：

  • 动态类型判断
  • 运算符重载
  • Python 对象创建
  • 引用计数
  • 异常处理

因此完成同一个运算，需要执行远多于 C++ 的机器指令。

什么时候 Cython 性能接近 C++

如果大量使用 cdef、cpdef、cimport、nogil：

生成的是 C 原生类型（int、double），而不是 PyObject *。

此时 CPU 执行的是 C 变量，性能可以非常接近 C/C++。

决定性能的不是 Cython，而是是否仍然在操作 PyObject。

C++ 能否使用 Python 扩展模块

可以，但需要初始化 Python Runtime。

因此即使没有任何 .py 文件，仍然需要 Python Runtime。

推荐的软件架构

工业软件通常采用：

优势：

  • Python：脚本、自动化、AI
  • 扩展模块：Python 接口层
  • Core Library：真正算法

核心算法只维护一份，既可供 Python 使用，也可供 C++ 程序直接调用。

总结

Python 扩展模块本质上就是：

一个基于 Python C API 开发的动态库。

对于 C++ 开发者来说：

  • Python C API 可以理解为一套普通的 C/C++ SDK
  • 扩展模块就是一个调用 Python C API 的动态库
  • .pyd（Windows）和 .so（Linux）只是不同平台上的动态库格式，本质没有区别

性能差异的根本原因不在于扩展模块本身，而在于：

扩展模块内部是在操作 Python 对象（PyObject），还是操作 C/C++ 原生类型。
