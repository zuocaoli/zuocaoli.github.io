AutoPIPE（09）— 附加数据：载荷与作用目标

2026-11-01AutoPIPE载荷支撑数据结构

整理 Xtra Data 工具组的功能，给出载荷与点、组件、支撑的引用方案，说明支撑两端、工况关联和反向查询的组织方式。

Xtra Data 给已有模型补充重量、集中力、位移、水动力参数和校核信息。它们的作用位置各不相同：有的关联点，有的关联整个管件，有的必须精确到某个支撑。

工具组中的数据并非同一类型

功能用途
Joint Type and User SIF指定接头类型、用户面内／面外应力增强系数等
Additional Weight添加附加重量及作用位置偏移
Concentrated Force在指定点施加力、力矩，并关联载荷工况
Imposed Displacement定义支撑或锚固的平移、转动，如基础沉降
Excel Support Displacements从 Excel 批量导入支撑位移
Hydrodynamic Data设置局部阻力、惯性和升力系数等
Cut Short定义安装时的冷紧、预截短或预加长量
User Weld Efficiency Factor指定局部焊接相关系数
Member Earthquake Factor调整管道、介质、保温等分布重量对应的地震作用
Point Earthquake Factor调整阀门、法兰和附加重量等集中重量对应的地震作用
Reference Point定义设备接口载荷评价的位置、坐标系和允许值
Piping Restraint Options控制特定规范中受约束／非受约束类校核的选项

这个工具组同时包含直接载荷、载荷生成参数、局部修正系数和结果评价信息。数据结构可以共享目标引用方式，但不能把所有条目都当成具有同一载荷工况语义的力或位移。

下面沿用上一篇的组件和几何点设计，只展开集中力、分布载荷与支撑位移的关联方案。代码属于研发示意，省略具体载荷参数和 ID 的实现。

先表达作用目标

PointRef 定位某个组件内的具体几何点，ComponentRef 定位整个组件，SupportRef 定位一条支撑记录。它们回答的是“作用在哪里”。

例如，在弯头 Near 点施加集中力，目标应包含弯头 ID 和 Near 点 ID。只保存“弯头 ID”，会丢失作用位置。

载荷记录关联目标与工况

LoadData 回答“施加什么”，LoadTarget 回答“施加到哪里”，loadCaseId 则把这条记录关联到载荷工况。同一个管件可以具有多条记录，各自指定工况、目标和参数。

场景目标引用关联路径
弯头 Near 点上的集中力PointRef载荷 → 弯头 → 几何点
直管上的分布载荷ComponentRef载荷 → 直管
支撑 S1 的基础沉降SupportRef位移记录 → 支撑 S1 → 被支承位置

具体载荷数据还需要自己的坐标系、方向、单位及必要的作用范围。这里只展示关联关系，不能把三个目标和三种数据的任意组合都视为有效输入。

支撑保存被支承位置与另一端目标

支撑的一端在管道上，另一端可能是地面、另一管道位置，或结构位置。可以分别定义：

supportedPoint 记录支承哪个管件的哪个点，connectedTo 记录另一端的目标，properties 记录约束方向、刚度及该类型支撑所需的其他参数。梁及其点由结构模型管理，这里通过 BeamId 引用。

对于上一篇的吊架模型，支承位置对应 B01，另一端对应梁 M2 上的 M1002。两端连接关系与弹簧属性共同描述其力学作用。

一个管道点可能安装多个支撑。给其中一个支撑施加强制位移时，必须保留 SupportId；仅靠管件 ID 和 PointId，无法区分该点上的不同支撑。

全局保存记录，索引用于反向查询

全局模型分别管理组件、支撑和载荷。沿用上一篇的网络结构，可以组织为：

loads 是载荷记录的主数据。选择一个管件时，可以通过索引汇集三类结果：直接关联组件的载荷、关联组件内部点的载荷，以及关联该组件上支撑的载荷。

如果需要在组件中保留 attachments 以便快速访问，应保存记录引用，或把它作为可重建的派生索引。不能让组件里的附件副本与全局载荷记录各自独立修改。

SIF、焊接系数等局部数据可以采用类似目标引用，但应按自身语义保存。界面都放在 Xtra Data 工具组中，并不意味着它们在模型中必须使用同一种记录类型。

关联时需要检查什么

检查示例
目标存在且归属正确PointId 确实属于引用的 ComponentId
数据类型与目标匹配支撑位移指向支撑，所选点允许施加对应载荷
工况有效LoadCaseId 指向已定义且适用的载荷工况
支撑两端引用有效梁、管道点或地面目标能够解析
删除后无悬空引用删除组件或支撑时，处理其载荷和相关索引

几何点能被拾取，不代表它能承载所有附加数据。例如 TIP 用于定义弯头几何，应用程序必须根据对象语义决定是否允许其成为某类载荷目标。

通过这些引用，组件、支撑、载荷和工况可以各自维护，又能沿稳定 ID 互相追溯。工程对象转换成分析节点和单元时，再把载荷与约束映射到对应的分析位置。
